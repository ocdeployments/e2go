## 6. Known coverage gaps

| Id | Gap | Impact | Mitigation |
|---|---|---|---|
| G1 | No admin persona | admin-positive paths (all /admin/*, /api/admin/*) are untestable; only the deny side is tested | create a dedicated QA admin in a staging project |
| G2 | No unpaid / sim-only / FDD-only / soft-deleted / unverified persona | paid-gate fall-through (/results, /simulator), FDD-only pass, /account-recovery for a real deleted user and e-mail-verification states are untested | seed one persona per state |

| G5 | Single browser engine (embedded Chromium) | Safari/WebKit and Firefox rendering, real-device touch and OS font rendering are untested | run the same queues on BrowserStack / real devices |
| G6 | Supabase project is shared with production | every authenticated E1 action lands in the production database; 429s are written to rate_limit_hits | a staging Supabase project or branch |
| G7 | Session lifecycle is untested | expired-token refresh, concurrent sessions, sign-out from the UI (never clicked) and cookie chunk rollover | a dedicated lifecycle test with a disposable account |

| G11 | LLM-backed features run with LLM keys disabled | generation, simulator scoring, FDD extraction, gap analysis and market analysis are exercised only through their error / empty states | a funded run with --allow-llm against a staging database |
